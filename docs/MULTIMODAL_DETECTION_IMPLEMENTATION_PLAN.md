# Multimodal detection implementation plan

Status: proposed implementation plan, 2026-09-26. Implement one phase per PR. This plan supersedes the sequencing in `DETECTOR_ARCHITECTURE_REVIEW.md` and expands `MODEL_EVALUATION_PLAN.md`; those documents and the historical `IMPLEMENTATION_REPORT.md` remain source records.

## Product contract and current baseline

The product evaluates **evidence of synthetic or manipulated media and document inconsistencies**. It does not determine whether an underlying event, expense, identity, or claim is true. A real photograph can depict a staged event; an AI-generated illustration can accompany a legitimate document. Never present an AI-generation score as a probability of fraud.

The current draft backend has FastAPI upload/job routes, optional database and R2 integration, metadata extraction, and one bounded OpenRouter vision call. That call sees one resized image, three sampled video frames, or up to three rendered PDF pages and returns a forced Real/Fake label with self-reported confidence. Jobs and batches still depend on process memory. There is no labeled accuracy result, independent pixel detector, temporal video analysis, PDF text/signature pipeline, calibrated score, or durable per-user cost control. The former VLM-to-three-text-critics jury was correlated because its critics saw the first model's prose rather than independent media evidence; it is retired in draft PR #14. Treat the current single-call path as a **manual-review screening baseline**, not a released detector.

The target API reports separate tasks: `synthetic_image`, `local_image_edit`, `face_manipulation`, `synthetic_video`, `document_integrity`, `document_field_consistency`, and `provenance`. Each task can be `supported`, `inconclusive`, `unsupported`, or `error`. A task result includes a finding (`evidence_present`, `evidence_not_found`, or `undetermined`), evidence locations, analysis coverage, model/policy/preprocessing versions, and limitations. A numeric likelihood appears only after task-specific held-out calibration. The top-level disposition remains `manual_review` until its release gate is met. Missing metadata, missing C2PA, no signature, low frame rate, or an editor name are observations, never fraud evidence by themselves.

## Shared architecture

```text
FastAPI intake -> immutable original in private object storage + SHA-256
              -> PostgreSQL job/evidence records -> bounded worker
              -> format router -> image | video | PDF analyzers
              -> versioned task evidence -> policy/abstention -> review UI/API
```

1. **Intake and access.** Authenticate users before paid or resource-intensive analysis. Apply tenant quotas, rate limits, file-size/page/duration/pixel limits, MIME sniffing, and idempotency keys before enqueueing. Store original bytes privately; derived crops, frames, OCR and thumbnails get their own hashes and lineage. Reject unsafe or unparseable inputs with a typed reason. Run PDF/video decoders in resource-limited workers. Give evidence a configurable retention period and deletion path; exclude raw media, OCR text, credentials and PII from logs.
2. **Durable execution.** Keep FastAPI as the API. Add PostgreSQL `jobs`, `job_attempts`, `artifacts`, `task_results`, and `model_usage` records. A separate worker atomically claims queued jobs with `FOR UPDATE SKIP LOCKED`, leases them, checkpoints task outputs, and retries transient failures with a bounded count. Make results idempotent by job ID + pipeline version; distinguish provider failure from `inconclusive`. Use the existing object-storage abstraction where configured. A PostgreSQL queue is sufficient for the first measured workload; reconsider a dedicated broker only after queue-depth/latency evidence. SQLite remains a local development fallback, not the production queue.
3. **Cost controls.** Default to zero paid VLM calls for deterministic checks. Make hosted vision an optional, capped review aid, with an approved model list, max images/pages/frames/tokens, per-job budget, per-tenant daily/monthly budget, and a provider account hard spend cap. Record provider-reported usage and cost; fail closed before a call when the estimated worst-case job budget is unavailable. No Featherless dependency. Run specialist models locally only when license, memory, latency and operating cost meet the same gate.
4. **Evidence contract.** Return factual signals, locations (`page`, `bounding_box`, `start_ms`/`end_ms`), source artifact hashes, coverage (pages inspected, sampled intervals, OCR quality), calibrated score only where validated, and an explicit `not_checked` for skipped branches. Preserve both favorable and adverse evidence. Separate C2PA/PDF signature *verification* from visual/statistical detection; a valid signature proves integrity and signer trust under a configured trust store, not factual truth. Keep unvalidated model prose as `observations`, never as independently verified evidence.

## Image method

**Question A: fully synthetic image.** Analyze a lossless decoded view derived from the original, retaining the original and transformation manifest. Benchmark a commercially usable pixel-based detector against the current VLM on the same labeled images; UniversalFakeDetect is only a candidate, since code license does not automatically clear checkpoint, backbone or data rights. Include modern unseen generators, camera images, screenshots, re-exports, crops and compression. Test full-frame and content-aware crops without hiding the whole-image context. Do not treat an enlarged or re-JPEGed VLM input as forensic pixels.

**Question B: local edit or face manipulation.** Route to a separate localization task; where faces are present, evaluate a face-specific detector with subject-disjoint data. Return masks/regions and their uncertainty only if a licensed model beats a simple baseline on held-out local edits. A whole-image synthetic score cannot answer whether one field, object or face was altered. Do not ship noncommercial research code/weights (for example, DeepfakeBench or TruFor) into the product.

**Question C: provenance.** Validate any C2PA manifest on the *original bytes* with a tested SDK and trust list. Report valid/trusted, valid/untrusted, invalid, absent, unsupported and verification error separately. Never infer that absent credentials imply manipulation. Use the VLM, if paid budget allows, to describe visible anomalies for a reviewer; its self-reported confidence is not fused as an independent forensic vote.

Image release gate: on an untouched, held-out and transformation-stratified set, show the chosen detector's false-positive rate at the intended review operating point, recall by generator/edit type, calibration/abstention, localization quality when applicable, p50/p95 latency and cost. Compare paired errors with the current screening baseline. If it does not improve the agreed cost-quality frontier, keep it experimental and retain manual review.

## Video method

1. Probe container, codec, frame rate, duration, rotation and audio with `ffprobe`. Preserve timestamps and original bytes. Fail early on limits or decode gaps, and report the portion of runtime actually inspected.
2. Detect shot boundaries, then sample bounded frames or short clips across scenes and time. Add denser samples around suspicious intervals or face tracks within a fixed compute budget. The present three evenly spaced frames remain a baseline for comparison, not a full-video verdict. A one-frame image detector may provide frame observations; validate its video aggregation separately.
3. Route **fully generated video** to a tested video-level/temporal candidate and **face swap/reenactment** to a face-track candidate. These have different labels and evaluation sets. Only add audio-synthetic or lip-sync checks as a separately scoped task when audio exists and rights-cleared labels are available. Never infer audio authenticity from silent frames.
4. Aggregate at segment and video levels with a calibrated, held-out policy; return suspicious timestamps, sampling coverage and uninspected spans. Abstain when duration, decode quality, face visibility or sample coverage is insufficient. The budgeted sampling policy is itself versioned and benchmarked against missed short edits.

Video release gate: subject/source/generator-disjoint tests for full generation and face manipulation, including short inserted edits, multiple shots, re-encoding and authentic low-quality clips. Report clip/video false-positive rate, event-level recall and timestamp localization, coverage/abstention, p95 runtime and cost. Use [AIGVDBench](https://openaccess.thecvf.com/content/CVPR2026/html/Ma_Your_One-Stop_Solution_for_AI-Generated_Video_Detection_CVPR_2026_paper.html) and [DeepfakeBench](https://github.com/SCLBD/DeepfakeBench) as protocol references after dataset and code-rights review; their reported performance is not our performance.

## PDF/document method

1. **Parse before rendering.** Classify born-digital, scanned, mixed, encrypted, and malformed PDFs. Use bounded text/object extraction (candidate `pypdf`) and page rendering (candidate `pypdfium2`); avoid unconstrained decompression/content streams. Extract page count, text spans/positions, forms, embedded images, annotations, attachments and revisions where supported. Record parser coverage. A visual rendering alone loses searchable text and structural evidence.
2. **Verify cryptographic integrity.** Validate embedded PDF signatures and post-signature changes with `pyHanko` under an explicit trust configuration. Check C2PA independently where the installed SDK supports the PDF format. Distinguish unsigned, valid/trusted, valid/untrusted, modified-after-signing, invalid, and unverifiable. An unsigned invoice is ordinary; a valid signature does not validate its amounts.
3. **Read pages.** Use OCR (candidate Tesseract) for scanned regions or when the extracted text layer is empty/unreliable. Retain page coordinates and OCR confidence. Render selectively for visual comparison and send embedded photos through the image method with clear parent-page lineage. Never label an entire PDF synthetic just because a contained stock image is synthetic.
4. **Check document claims.** Start with one or two declared document types (for example, invoices and receipts), not arbitrary PDFs. Normalize fields with page citations. Apply deterministic arithmetic, date and repeated-field checks; compare to trusted external records only when an authorized integration exists. Use a VLM only for low-confidence field extraction or reviewer context under a cap. Conflicts are `inconsistency` findings, not proof of forgery. Generic AI-written-text detection stays out of the production fraud verdict: paraphrasing and domain shifts make unsupported author attribution especially risky.

PDF release gate: born-digital, scan and mixed-page fixtures with known signatures/revisions and controlled field edits. Measure field-extraction precision/recall, OCR error and coverage, arithmetic-check false positives, signature-state correctness, page-level localization, p95 runtime and cost. The output must identify skipped/unreadable pages. Do not release a universal “document fake” label.

## Evaluation, decision policy and rollout

Create a consented, rights-cleared evidence registry with immutable item hashes, source/generator/edit tool and version, capture or creation path, transformations, document type, timestamps, licenses and independent reviewer labels. Label `authentic`, `fully_generated`, `locally_edited`, `face_manipulated`, and document-specific field/signature states separately; an unknown-source web image is exploratory, not ground truth. Split by source, person and generator family before transformations; keep a locked test set and a drift set of newly released generators. Include benign processing (resizing, screenshots, OCR scans, recompression) so the model cannot win on export artifacts. Keep research benchmark assets out of the product unless their rights permit use.

For each candidate, freeze data hashes, preprocessing, model/checkpoint, prompt, threshold and policy versions. Run the existing VLM baseline and candidate on the same pilot set with a capped budget. Report per-class FPR/TPR, precision/recall, AUROC/AUPRC where meaningful, confidence intervals, calibration error, abstention/coverage, per-source and transformation slices, invalid/error rate, provider-reported spend, and p50/p95 latency. Localization tasks also report region/interval overlap and event recall. Use a separate validation set to select thresholds at an agreed false-positive operating point; touch the locked test set once per candidate decision. Store run manifests and per-item outputs for reproducibility. No universal accuracy claim follows from synthetic smoke tests.

**Fusion is a policy layer, not a jury.** First report independent task findings side by side. Only fit/calibrate an ensemble after a held-out paired error analysis shows that a second signal adds value over the best single signal at an acceptable cost and false-positive rate. Never majority-vote several prompts or critics reading the same VLM narrative. A high-stakes adverse outcome always requires a reviewer until a separately approved, measured policy exists. Disagreement, missing coverage and out-of-distribution inputs route to review. Version policy and thresholds in every stored result; historical scores from the old jury and new pipeline must remain segregated in analytics.

Roll out behind a feature flag in shadow mode, then to a small authenticated cohort. Watch false-positive reports, abstention, processing failures, queue depth, p95 latency and spend per modality. Stop promotion if a target gate regresses. The frontend then shows the actual questions tested, evidence locations and skipped checks; it never displays a generic “fraud percentage.”

## Phase-by-phase PR sequence

| Phase / PR | Deliverable | Exit gate |
| --- | --- | --- |
| **0 — evidence and baseline** | Evidence registry schema, rights/label protocol, versioned offline runner, capped paired baseline on a small pilot; publish measured cost/errors and choose explicit FPR, coverage, latency and spend targets with the product owner. | Reproducible per-item outputs and run manifest; no model promotion from smoke tests. If labeled items are unavailable, ship harness and fixtures but mark accuracy gate pending. |
| **1 — durable backend** | Authenticated upload/job API, private artifact lineage, Postgres-backed leased worker, idempotency/retries, quotas and spend gate, typed task-result schema, migrations. Preserve current endpoint compatibility during transition. | Restart and concurrent-worker tests prove no lost/duplicate chargeable jobs; limits, retention and failure states covered; production deploy and migration verified. |
| **2 — image** | Original-byte C2PA check, pixel-detector adapter and benchmark, optional local/face branch only after task-specific labels, reviewed image result. | Commercial rights verified for every shipped component; held-out image and cost gate met, otherwise only evidence/experimental output. |
| **3 — PDF** | Bounded parser and renderer, signatures, OCR, page lineage and first declared document schema/rules. | Known signature/revision cases and held-out document field/false-positive gate met; unsupported types abstain. |
| **4 — video** | Scene-aware bounded sampling, timestamped frame/face tracks, candidate temporal detector, segment aggregation and coverage report. | Held-out full-generation and face-edit gates met separately; short-edit miss rate and worst-case cost measured. |
| **5 — decision and product UI** | Calibrated per-task policy only where justified, reviewer workflow, evidence-linked frontend redesign, historical result versioning and shadow rollout. | Human review can reproduce each finding; no generic fraud score; measured operational and false-positive targets hold in the cohort. |

Merge the currently stacked backend PRs in order before starting phase PRs, or explicitly rebase the first phase onto their final merged state. Each phase should be one reviewable PR with its own measured gate; a phase that fails its gate remains experimental rather than being silently promoted. The first actionable work after this plan is **Phase 0**, since model choice, thresholds and any ensemble claim depend on labeled paired evidence.

## Research and implementation references

- [C2PA explainer](https://spec.c2pa.org/specifications/specifications/2.2/explainer/Explainer.html) and [c2pa-rs format/feature support](https://github.com/contentauth/c2pa-rs/blob/main/docs/usage.md): signed provenance and trust semantics; SDK support must be verified on our file formats/runtime.
- [AIGIBench](https://papers.neurips.cc/paper_files/paper/2025/hash/fb693c67f61e5321746ffce8b6fdd2d0-Abstract-Datasets_and_Benchmarks_Track.html), [RRDataset](https://openaccess.thecvf.com/content/ICCV2025/papers/Li_Bridging_the_Gap_Between_Ideal_and_Real-world_Evaluation_Benchmarking_AI-Generated_ICCV_2025_paper.pdf) and [Community Forensics](https://openaccess.thecvf.com/content/CVPR2025/papers/Park_Community_Forensics_Using_Thousands_of_Generators_to_Train_Fake_Image_CVPR_2025_paper.pdf): cross-source, compression and real-world image generalization motivate our held-out/transform testing.
- [AIGVDBench](https://openaccess.thecvf.com/content/CVPR2026/html/Ma_Your_One-Stop_Solution_for_AI-Generated_Video_Detection_CVPR_2026_paper.html) and [DeepfakeBench](https://github.com/SCLBD/DeepfakeBench): separate generated-video and face-deepfake protocols; DeepfakeBench is CC BY-NC and its code is not a product dependency.
- [pypdf extraction limits](https://github.com/py-pdf/pypdf/blob/main/docs/user/extract-text.md), [pypdfium2 rendering/licensing](https://github.com/pypdfium2-team/pypdfium2), [Tesseract OCR](https://github.com/tesseract-ocr/tesseract), and [pyHanko signature validation](https://docs.pyhanko.eu/en/v0.29.0/cli-guide/validation.html): candidate PDF components, subject to pinned-version and bundled-license review.
- [AI-text detection robustness study](https://arxiv.org/abs/2303.11156): reason to keep AI-written-text authorship out of an unvalidated fraud verdict.
- [PostgreSQL row-locking documentation](https://www.postgresql.org/docs/current/sql-select.html): `SKIP LOCKED` permits concurrent consumers of a queue-like table; worker lease/retry behavior remains our responsibility.
